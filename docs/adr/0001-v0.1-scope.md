# ADR 0001 — v0.1.0 scope decisions

- **Status:** Accepted
- **Date:** 2026-11-03

## Decisions

1. **Protocol v1 is frozen at `lmpu/1`.** Additive fields are allowed; breaking
   changes wait for `lmpu/2`. The JSON Schema is generated from Pydantic models
   and committed.
2. **One trace schema.** `lmpu.host_metrics.v1` is the only metrics payload.
   The trace schema is frozen alongside the protocol schema.
3. **Three canonical demos only.** Kernel crash/recovery, S1 park/resume, and
   16 MiB context protection. Each demo has executable assertions; no
   demo-only behavior.
4. **One minimal dashboard.** Read-only, polling-based, SSE for live updates.
   Scenario authoring, multi-task YAML, and rich filters are deferred.
5. **One SDK surface.** `LMPUClient` is a thin async JSON-RPC client over the
   Unix socket. Higher-level agent frameworks remain out of scope.
6. **Optional heavy dependencies stay isolated.** vLLM, Outlines, and full host
   extras remain optional environments. Python 3.12–3.14 are supported.
7. **No speculative infrastructure.** No server-side vector database, no
   built-in HTML/JS scenario DSL, and no automatic P8 extension surface in
   v0.1.0.
8. **Changed-file lint/type policy.** Legacy modules are cleaned in one hygiene
   pass before D3; new modules are strict.
9. **Release artifact is reproducible and inspectable.** Build a wheel and
   sdist, generate checksums and an SBOM, and sign the artifact when a release
   key is available.

## Consequences

- The schema files must be regenerated after any protocol-model change.
- Trace consumers can rely on discriminators and required fields, not on
  optional payload completeness.
- Deferred product work cannot be presented as v0.1.0 functionality.
